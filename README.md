## 보드 기능

팀 PIN(조회 PIN) 하나로 들어오면 **누구나** 일정·주요업무를 추가·수정·삭제할 수 있습니다. 관리 작업(대시보드 관리, 사용자 관리, JSON 가져오기)만 관리자 PIN(편집 PIN)이 필요합니다.

### 공통

- **넓게 보기**: 각 탭 요약 카드 오른쪽 위 ⤢ 버튼, ⋮ → 넓게 보기, 단축키 **W**. PC는 왼쪽 사이드바를 접고 필터를 한 줄로 올려 목록을 전체 폭으로(업무 카드 3열, 1500px~ 4열, 1900px~ 5열). 폰은 요약 카드를 숨기고 가능한 기기에서는 브라우저 전체화면. 왼쪽 아래 **기본 보기**로 복귀(일정표는 달력/목록 전환도 그 옆). 설정은 기기에 기억
- **키워드 검색**: 세 탭 모두 같은 알약 모양 검색창. 항상 **+ 추가 버튼 왼쪽** 같은 줄(PC는 사이드바 안, 폰·넓게 보기는 화면 아래 떠 있는 버튼 옆). 제목·장소·담당·메모·구분·날짜를 부분 일치로 찾고 맞는 글자를 노랗게 표시. 띄어쓰기로 여러 단어를 넣으면 **모두 들어간 항목만**(AND) 찾음. 일정표는 지난 일정까지 포함해 "'키워드' 검색 결과 N건 · M일 (시작~끝)"을 보여주고, 달력에서는 해당 날짜 칸이 금색으로 표시됨. `/` 키로 검색창 이동, Esc 또는 × 로 지움
- **주요 일정 강조**: 구분에 '주요업무'가 든 일정은 목록·달력에서 카드 전체가 금색 톤 + ★ 표시(완료 업무가 녹색인 것과 같은 방식). Attention 의 연동 카드도 같은 톤

### Schedule (일정표)

- 날짜별 그룹, 오늘 강조, 지난 일정은 항상 접힘("지난 일정 N건 펼치기" / 펼친 뒤 "접기"). 진행 중인 여러 날 일정도 접힌 상태에서는 오늘 이전 날짜를 숨기고 버튼에 "진행 중 일정의 지난 날짜 M일"로 표시. 예정 일정이 하나도 없어도 지난 일정은 접어 두고 안내만 표시. 달력에서 지난 날짜를 누르거나 지난 날짜로 저장하면 그 자리를 보여 주기 위해 자동으로 펼침
- 구분 11종: **주요업무 · ICTC · 지휘역량팀 · 시민체험팀** · 사고자 · 교육 · 평가 · 회의 · 방문 · 출장 · 기타 + **직접 입력**(선택 칸 끝 **＋ 직접 입력**, 10자 이내·띄어쓰기 없이. 이름에서 정해지는 고유 색, 한 번 쓰면 모두의 필터·선택 칸에 나타남. 기기에도 최근 20개 기억). **여러 개 선택** 가능, 첫 번째가 기준색. 화면 우선순위 1 주요업무 → 2 ICTC → 3 지휘역량팀 → 4 시민체험팀 → 5 사고자 → 6 나머지: 칩은 이 순서로 앞에 고정(나머지는 0건 뒤로), 같은 날짜·같은 상태 안에서도 이 순서로 정렬. 주요업무·개인업무의 분류에도 ICTC · 지휘역량팀 · 시민체험팀이 맨 앞에 있음(연동 카드가 그 앞)

### Individual Log (개인업무)

- 행정전화번호 **뒤 4자리 + 비밀번호 4자리**만으로 사용. 등록되지 않은 번호면 "새로 등록할까요?" 확인 뒤 그 자리에서 등록(이름은 '직원 1234' 로 시작, ⋮ → **내 이름 변경**으로 바꿈). 비밀번호는 서버에 해시로만 저장되고 본인만 알며, 잊으면 담당자가 초기화. 비밀번호 변경은 ⋮ → 내 비밀번호 변경(PC는 왼쪽 버튼). 예전에 이름으로 들어가던 사용자는 담당자가 비밀번호를 초기화해 주면 됨
- 연도 · 월 필터, 월별 묶음(기한이 없으면 등록일 기준). 2027년 이후에도 과거 업무를 연도별로 조회
- 로그아웃: 이름 카드의 버튼 또는 ⋮ → 개인업무 로그아웃. 로그인은 기기에 저장되고, 다른 기기에서 같은 정보를 넣으면 같은 내용
- **엑셀 가져오기**: ⋮ → 엑셀로 개인업무 가져오기(PC는 왼쪽 버튼). .xlsx/.xls/.csv 의 첫 시트를 읽어 업무명·기한·상태·구분·비고 열을 자동으로 찾고(열 이름이 달라도 화면에서 직접 지정), 미리보기에서 고른 행만 내 개인업무로 추가. 같은 업무명+기한이 이미 있으면 '이미 있음'으로 표시해 기본 제외. 상태는 완료/진행/보류/예정 계열 단어로, 구분은 6개 분류로 자동 변환(못 맞추면 기타 + 원문을 비고에). 파일은 브라우저에서만 읽고 서버로 올라가지 않음. 빈 양식(.xlsx)도 내려받을 수 있음. 파서는 SheetJS(`assets/vendor/`, Apache-2.0)
- JSON 내보내기 (백업)는 관리자 메뉴라서 관리자 모드에서만 보이고, Individual Log 탭에서 누르면 그 기기에 로그인한 사람의 업무만 내려받음. JSON 가져오기는 없음(엑셀 가져오기 사용). 대시보드와 무관하게 사람별 저장. 로그인 이름은 41망 글쓴이 이름으로도 쓰임

## 데이터 저장 방식

**현재 운영 모드는 Supabase 모드입니다.** `config.js` 에 프로젝트 URL·anon 키가 들어 있어 주소 하나로 어디서나 같은 데이터를 봅니다.

| 모드 | 조건 | 동작 |
|---|---|---|
| **Supabase** (현재 운영) | `config.js` 에 URL·anon key | 외부 클라우드 DB(싱가포르 리전). RPC 함수로만 접근, PIN 검증. `pollSeconds`(기본 30초)마다 갱신 |
| 로컬 서버 (대안) | [ZIP](https://github.com/kwonyujin119/test2/raw/main/dist/ictc-board-server.zip) 을 PC에서 실행 | DB가 PC의 `D:\일정표,주요업무\ictc.db`. 같은 네트워크 팀원이 `http://PC주소:8080` 접속. PC가 켜져 있을 때만 |
| 미리보기(테스트 모드) | `config.js` 두 값이 빔 | 각자 브라우저(localStorage)에만 저장. 화면 상단에 "테스트 모드" 배너 |

세 모드의 화면과 기능은 같고 저장 위치만 다릅니다. 프론트에서 호출 이름·파라미터를 바꾸면 `server/supabase.sql` 함수와 `server/ictc_server.py` 핸들러를 함께 바꿉니다([`CLAUDE.md`](CLAUDE.md)).

### Supabase 모드 설정 (약 10분, 1회) — 이미 완료됨

1. https://supabase.com 가입 → **New project**. 현재 운영 프로젝트는 Southeast Asia (Singapore, `ap-southeast-1`).
2. 좌측 **SQL Editor** → **New query** → 저장소의 `server/supabase.sql` 전체 붙여넣기. 파일 상단 `'1234'`(편집 PIN)와 `'0000'`(조회 PIN)을 팀 PIN으로 바꾼 뒤 **Run**. 기본값은 **최초 설치 때만** 적용되고, 다시 실행해도 기존 PIN·데이터는 유지됩니다.
3. 키 복사: **Project Settings**(톱니) → **API Keys** → Publishable key(`sb_publishable_…`) 또는 Legacy 탭의 **anon public**. `service_role` / `sb_secret_…` 는 절대 쓰지 않습니다. **Data API** → **Project URL**(`https://프로젝트ID.supabase.co`).
4. `config.js` 의 `supabaseUrl`, `supabaseAnonKey` 에 붙여넣고 커밋·푸시. 1~2분 뒤 Pages 반영.
5. https://kwonyujin119.github.io/test2/ 를 열면 PIN 잠금 화면이 뜹니다.

anon 키는 브라우저에 노출되도록 설계된 공개 키입니다. 모든 요청이 PIN을 검증하는 DB 함수만 거치므로 키만으로는 데이터를 읽거나 쓸 수 없습니다(테이블 직접 접근은 차단).
무료 플랜은 1주일간 요청이 없으면 프로젝트가 일시중지되며, 대시보드에서 Restore 하면 데이터는 그대로 복구됩니다.

### SQL 자동 적용 (1회 설정, 2분) — 이미 완료됨

`server/supabase.sql` 이 바뀌어 푸시되면 GitHub Actions "Apply Supabase SQL" 이 DB에 자동 실행합니다.

1. Supabase 대시보드 상단 **Connect**(PC: 초록 글자 버튼, 휴대폰: 프로젝트 이름 오른쪽 플러그 아이콘) → **Connection string** → Type **URI** → Method **Session pooler** 문자열 복사.
   `postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres` 형태(`aws-0` 은 `aws-1` 일 수도 있음). `[YOUR-PASSWORD]` 를 대괄호까지 지우고 DB 비밀번호를 넣습니다.
   비밀번호를 모르면 Project Settings → **Database** → **Reset database password**. 영문·숫자만 쓰면 주소에 넣을 때 문제가 없습니다.
   "Direct connection"·"Transaction pooler" 주소는 GitHub 서버에서 접속이 안 됩니다. 반드시 Session pooler.
2. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**. Name `SUPABASE_DB_URL`, Secret: 1번 값.
3. 확인: 저장소 **Actions** 탭 → "Apply Supabase SQL" → **Run workflow** → 초록 체크.

이 접속 문자열은 DB 전체 권한입니다. 채팅·코드·문서에 적지 않고 GitHub Secret 에만 둡니다.

- 편집 PIN은 조회 PIN을 겸합니다. 조회 PIN을 빈 문자열로 두면 링크를 아는 누구나 들어옵니다.
- PIN을 바꾸면 직원 기기에 잠금 화면이 다시 뜹니다. 새 PIN을 먼저 공지하세요.
- PIN을 연속으로 틀리면 서버가 응답을 늦추고, 로컬 서버는 10분간 차단합니다(무차별 대입 방지).
- 팀 PIN만으로 누구나 지울 수 있습니다. 지운 항목은 휴지통에 **30일** 보관되며, 관리자 모드에서 ⋮ → **휴지통** → **복구** 로 되살립니다(SQL 로도 가능, [운영 가이드 5장](docs/담당자-운영가이드.md#5-백업과-복구)). JSON 내보내기도 주기적으로 받아 두세요.

## JSON 형식 (내보내기·가져오기)

```json
// schedule.json 항목
{ "id": "s001", "date": "2026-10-22", "endDate": "2026-10-24",
  "start": "09:00", "end": "18:00", "title": "일정 제목",
  "place": "장소", "owner": "담당", "tags": ["교육", "주요업무"], "note": "메모" }
// tags: 주요업무 / ICTC / 지휘역량팀 / 시민체험팀 / 사고자 / 교육 / 평가 / 회의 / 방문 / 출장 / 기타 중 1개 이상. 옛 파일의 "tag": "교육" 도 읽힘
// endDate 가 없거나 date 와 같으면 하루 일정

// tasks.json 항목
{ "id": "t001", "category": "교육운영", "title": "업무명", "status": "진행중",
  "due": "2026-11-14", "owner": "담당", "detail": "상세 내용" }
// 일정에서 연동된 카드는 "id": "sch-<일정ID>", "fromSchedule": "<일정ID>" 가 붙음
```

`status`는 `예정` / `진행중` / `완료` / `보류`, `category`는 `ICTC` / `지휘역량팀` / `시민체험팀` / `교육운영` / `행정` / `시설장비` / `대외협력` / `예산` / `기타`. `id`가 없으면 자동 생성. 가져오기는 **현재 대시보드의 해당 탭 전체를 교체**합니다(개인업무는 가져오기 없음).
카테고리 이름을 바꾸려면 `index.html` 스크립트 상단 `CATEGORIES`, `TASK_CATEGORIES` 와 같은 이름의 색 변수(`--c-*`, `--t-*`)를 함께 수정합니다.

## 화면에 뜨는 오류 문구와 뜻

문구는 `index.html` 의 `ERR` 표(서버 오류 코드 → 한국어)와 화면 안내 토스트 그대로입니다. 전체 표(문구 → 원인 → 직원이 할 일 → 담당자가 할 일)는 [운영 가이드 10장](docs/담당자-운영가이드.md#10-오류-문구-해석표-화면-캡처를-받았을-때). 자주 보는 것만 요약(앞부분만 적음):

| 문구 | 뜻 | 조치 |
|---|---|---|
| 팀 PIN이 필요해요… / 팀 PIN이 올바르지 않아요… | 잠금 화면 PIN 불일치, 또는 PIN이 바뀜 | 담당자에게 현재 PIN 확인. 관리자는 ⋮ → 팀 PIN 다시 입력 |
| 관리자 PIN을 입력하세요. 담당자 전용 기능이에요 (입력창) / 관리자 PIN이 필요해요 | 관리 작업 버튼(⋮ 맨 아래 관리자 로그인, 대시보드 +)을 누름·취소함 | 직원은 취소. 조치 불필요 |
| 관리자 PIN이 올바르지 않아요… | 편집 PIN 불일치. 기기에 저장된 PIN은 지워짐 | 담당자 PIN으로 다시 |
| 틀린 시도가 너무 많아요. 10분 뒤에 다시 하세요 | PIN을 연속으로 틀림(로컬 서버 모드만. Supabase 는 0.8초 지연) | 10분 뒤 재시도 |
| 뒤 4자리 숫자를 입력하세요 / 행정전화 뒤 4자리(숫자)를 확인하세요 / 비밀번호는 숫자 4자리예요 | 개인업무 입력 형식 오류 | 숫자 4자리 |
| ○○○○ 번호는 아직 등록되지 않았어요 … 새로 등록할까요? (확인창) | 처음 쓰는 번호 | 번호가 맞으면 확인 → 그 자리에서 등록 |
| 비밀번호가 맞지 않아요 | 개인업무 비밀번호 불일치(v4 이전 이름 로그인 사용자 포함) | 잊었으면 담당자가 사용자 관리 → 비밀번호 로 초기화 |
| 등록되지 않은 번호예요… / 이미 등록된 번호예요… | 등록 상태 불일치 / 번호 중복 | 새로고침 후 다시 / 담당자가 다른 4자리를 정해 줌 |
| 개인업무 로그인이 풀렸어요… | 담당자가 비밀번호를 초기화했거나 사용자를 삭제함 | 새 비밀번호로 다시 로그인 |
| 입장코드가 맞지 않아요… / 입장코드가 바뀌었어요. 다시 입장하세요 / 없는 톡방이에요… | 41망 입장코드 불일치·변경, 톡방 삭제 | 담당자에게 현재 코드 확인 |
| 글은 500자까지예요 / 한 번에 10개까지 보낼 수 있어요 / 한 번에 100 MB 까지 보낼 수 있어요 / '파일명' 은 파일당 한도(…)를 넘어요 | 41망 글·첨부 한도(화면 검사) | 나눠서 보내기 |
| 파일이 너무 커요. 서버 한도(무료 요금제는 파일당 50MB)… / 보낼 수 없는 파일 형식이에요… / 파일이 끝까지 올라가지 않았어요… | 41망 첨부 서버 거부 | 50MB 이하·허용 형식으로. 계속되면 담당자 |
| 파일 저장소가 아직 준비되지 않았어요. 담당자에게 알려 주세요(SQL 재적용) | Storage 버킷 `sail41` 없음 | 담당자가 SQL 재적용(운영 가이드 8장) |
| 같은 이름의 대시보드가 이미 있어요 / 기본 대시보드는 삭제할 수 없어요 | 대시보드 관리 제한 | 다른 이름 사용 / 기본 보드는 유지 |
| 항목 번호가 없어요… / 종류 오류예요… | 가져온 JSON 형식 문제 또는 화면 상태 꼬임 | 새로고침. 파일의 `items` 배열과 필드 확인 |
| 보관된 항목이 없어요. 30일이 지나 지워졌을 수 있어요 | 이미 복구됐거나 30일이 지남 | ⋮ → 휴지통 목록 새로 확인 |
| 서버에 연결할 수 없어요. 와이파이·데이터 연결을 확인하고 다시 시도하세요 / 서버에 연결하지 못했어요 / 불러오기 실패: … / 연결 안 됨 · … | 네트워크 또는 Supabase 일시중지 | 잠시 후 "다시 시도". 계속되면 담당자가 Supabase 에서 Restore |
| 서버 설정이 최신이 아니에요. 담당자에게 알려 주세요(SQL 재적용) | DB에 최신 SQL이 적용되지 않음(영문 'Could not find the function…' 을 화면이 번역) | 담당자가 Actions 자동 적용 확인 또는 SQL Editor 에서 `server/supabase.sql` 재실행 |
| 연결 키가 맞지 않아요. 담당자에게 알려 주세요 | anon 키 오류(영문 'Invalid API key' 를 화면이 번역) | `config.js` 키와 Supabase API Keys 대조 |
| 서버에 문제가 생겼어요. 잠시 뒤 다시 시도하고, 계속되면 담당자에게 알려 주세요 | 서버 내부 오류(5xx) | 잠시 뒤 재시도. 계속되면 담당자(로컬 서버는 서버 창 [오류] 확인) |
| 서버 오류예요 (코드 N). 잠시 뒤 다시 시도하세요 | 번역표에 없는 서버 응답 | 새로고침. 재현되면 코드와 함께 보고 |
| 영문 대문자 코드만 뜸(ITEM_TOO_LARGE, BOARD_NOT_FOUND, ITEMS_REQUIRED, JSON_INVALID, NOT_FOUND) | 서버가 던지지만 `ERR` 표에 번역이 없는 코드(항목 64KB 초과, 지워진 대시보드에 저장, 로컬 서버 내부 오류) | 새로고침. 재현되면 보고 |

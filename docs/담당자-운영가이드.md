# 담당자 운영 가이드

대상: 보드 담당자(편집 PIN 보유, Supabase·GitHub 계정 소유). 직원 안내는 [`직원안내.md`](직원안내.md).

용어: 화면에서 직원에게 보이는 **"팀 PIN"이 조회 PIN**, **"관리자 PIN"이 편집 PIN** 입니다. 이 문서는 SQL 함수 이름과 맞추기 위해 조회 PIN·편집 PIN 으로 쓰고, 화면 문구를 인용할 때는 팀 PIN·관리자 PIN 으로 씁니다.

## 0. 급할 때 바로 찾기

| 상황 | 할 일 |

| 직원이 개인업무 비밀번호를 잊음 | 관리자 모드 → ⋮ → **개인업무 사용자 관리** → 그 사람 줄의 **비밀번호** → 새 4자리 정해 알려 줌. → 3장 |
| 41망 입장코드를 바꾸고 싶음 | 관리자 모드 → 말풍선 → 톡방 옆 **열쇠** 아이콘 → 새 코드. 바꾸면 모든 직원이 다시 입장. → 3장 |
| 화면에 "서버에 연결할 수 없어요…" 또는 "서버에 연결하지 못했어요" | Supabase 프로젝트가 잠들었는지 확인(7일 미사용) → **Restore project**. → 6장 |

| 화면에 뜬 오류 문구가 무슨 뜻인지 | → 10장 오류 해석표 |

### 관리자 모드 켜기 · 끄기

- 켜기 (둘 중 하나):
  1. ⋮ 메뉴 **맨 아래 "관리자 로그인"** → "관리자 PIN을 입력하세요. 담당자 전용 기능이에요" 창에 편집 PIN.
  2. 상단 **과 이름▾ 를 0.7초 길게 누르기** → 같은 창.
  3. 또는 대시보드 **+** 같은 관리 작업을 누르면 PIN을 묻고, 맞으면 그대로 켜집니다.
- 켜지면: 화면 테두리가 초록 그라데이션, SAIL:41 옆 "● 관리자" 배지, ⋮ 메뉴에 관리 항목 전부(JSON 내보내기 (백업) · JSON 가져오기 (통째로 교체) · 대시보드 이름 변경/삭제 · 팀 PIN 다시 입력 · 개인업무 사용자 관리 · 휴지통 · 관리자 모드 해제). 폰에서는 **새 대시보드 추가**도 ⋮ 에 보입니다.
- 끄기: ⋮ → **관리자 모드 해제**. 공용 PC에서 관리 작업을 했다면 꼭 끄세요. 켜진 채 두면 그 기기를 쓰는 누구나 대시보드를 지울 수 있습니다.
- 편집 PIN을 틀리면 "관리자 PIN이 올바르지 않아요. 담당자(관리자)만 쓰는 기능이에요"가 뜨고 기기에 저장된 PIN은 지워집니다(관리자 모드 해제됨).

## 3. PIN · 사용자 · 41망 관리

### 화면에서 (관리자 모드)

| 할 일 | 위치 (화면 글자 그대로) |
|---|---|
| 등록된 개인업무 사용자 보기 | ⋮ → **개인업무 사용자 관리** (이름 · 뒤 4자리 · 개인업무 건수 · 등록일) |
| 개인업무 비밀번호 초기화 | 사용자 관리 → 그 사람 줄 **비밀번호** → "새 비밀번호 4자리(숫자)" 입력 → 본인에게 알려 주고 ⋮ → 내 비밀번호 변경으로 바꾸게 함 |
| 개인업무 이름 정정 | 사용자 관리 → **이름** → 바른 이름. 업무는 그대로 남음 (삭제 후 재등록은 개인업무가 지워짐) |
| 개인업무 사용자 삭제(그 사람 개인업무 포함) | 사용자 관리 → **삭제**. 개인업무는 휴지통 30일 |
| 41망 입장코드 변경 | 말풍선 → 톡방 목록에서 톡방 오른쪽 **열쇠** 아이콘 → "새 입장코드(4자리 이상)". 바꾸면 모든 직원이 다시 입장 |
| 41망 톡방 이름 변경 · 코드 변경 · 삭제 | 톡방 안 오른쪽 위 **연필** 아이콘 → "1 = 이름 변경, 2 = 입장코드 변경, 3 = 톡방 삭제" 중 숫자 입력 |
| 41망 톡방 추가 | 톡방 목록 맨 아래 **+ 톡방 추가** → 이름(부서명) → 입장코드(4자리 이상) |
| 41망 글 삭제(누구 글이든) | 글 옆 **삭제**, 또는 길게 누르기/우클릭 → **삭제**. "(삭제된 메시지)" 자리로 남고 휴지통 30일 |
| 팀 PIN 잠금 화면 다시 열기(이 기기) | ⋮ → **팀 PIN 다시 입력** (서버의 PIN을 바꾸는 게 아니라 이 기기에 저장된 값을 지움) |

화면에서는 **조회 PIN·편집 PIN 자체를 바꿀 수 없습니다.** 아래 SQL 로 바꿉니다.

### SQL 로 (Supabase → SQL Editor → New query → 붙여넣고 Run)

| 할 일 | SQL |
|---|---|
| 편집 PIN 변경 | `select ictc_set_pin('기존편집PIN', '새편집PIN');` (4자 이상) |
| 조회 PIN 변경 | `select ictc_set_view_pin('편집PIN', '새조회PIN');` |
| 조회 PIN 없애기(링크만 알면 누구나) | `select ictc_set_view_pin('편집PIN', '');` |
| 현재 PIN 확인 | `select * from ictc_settings;` |
| 톡방 입장코드 변경 | `select ictc_chat_set_code('편집PIN', '톡방id', '새코드');` 톡방 id: `ictc`(지휘역량강화센터) · `edu-support`(교육지원과) · `edu-plan`(교육기획과) · `training`(훈련운영과). 화면에서 추가한 톡방은 `r…` 로 시작하는 난수 id |
| 톡방 추가 · 이름 변경 · 삭제 | `select ictc_chat_room_add('편집PIN','id','이름','코드');` / `select ictc_chat_room_rename('편집PIN','id','새이름');` / `select ictc_chat_room_delete('편집PIN','id');` |
| 톡방 목록·id 확인 | `select id, name, sort from ictc_chat_rooms order by sort;` (SQL Editor 는 표를 직접 읽을 수 있음. 코드는 해시만 있어 보이지 않음) |
| 개인업무 비밀번호 초기화 | `select ictc_user_reset_pin('편집PIN', '뒤4자리', '새비밀번호4자리');` |
| 개인업무 이름 정정 | `select ictc_user_rename('편집PIN', '뒤4자리', '바른이름');` |
| 등록된 개인업무 사용자 보기 | `select * from ictc_users_list('편집PIN');` |
| 개인업무 사용자 삭제 | `select ictc_user_delete('편집PIN', '뒤4자리');` |

- 입장코드 기본값(지휘역량강화센터 5948 · 교육지원과 5914 · 교육기획과 5926 · 훈련운영과 5527)은 **최초 설치 때만** 들어가며, 설치 뒤 바꾸길 권장합니다. 코드는 서버에 해시로만 저장되어 담당자도 조회할 수 없으니 바꾼 값을 따로 메모하세요.
- PIN을 바꾸면 모든 직원 기기에 잠금 화면이 다시 뜹니다. **바꾸기 전에** 새 PIN을 공지하세요. 편집 PIN은 조회 PIN을 겸합니다.
- PIN·입장코드·비밀번호를 틀리면 서버가 0.8초 늦게 답합니다(무차별 대입 방지). 정상 사용에는 영향 없습니다.
- 개인업무 열쇠는 뒤 4자리 + **비밀번호 4자리**(본인이 정함, 서버에는 해시만 저장. 담당자도 볼 수 없음).
- 등록은 본인이 뒤 4자리 + 비밀번호만 넣으면 끝나고(확인창 한 번), 이름은 '직원 1234' 로 시작합니다. 본인이 ⋮ → **내 이름 변경**으로 바꾸게 안내하고, 안 바꾼 사람은 사용자 관리 **이름** 버튼으로 정해 주세요. 41망 글쓴이 이름도 이 이름을 따릅니다.
- v4 이전(이름으로 로그인하던) 사용자는 비밀번호가 '이름' 그대로라 새 화면(숫자 4자리)으로는 못 들어옵니다. 사용자 관리 **비밀번호**로 새 4자리를 정해 알려 주세요.
- 같은 행정전화를 두 명이 쓰면 둘째 사람은 "이미 등록된 번호예요"로 막힙니다. 안 쓰는 4자리(예: 내선번호)를 정해 주고 그 번호로 등록하게 하세요.

## 4. 대시보드 관리 (화면에서, 관리자 모드)

- 추가: PC는 과 이름▾ 옆 **+**, 폰은 ⋮ → **새 대시보드 추가** → 이름 → 편집 PIN. 대시보드마다 일정·주요업무가 따로 저장됩니다. 개인업무·41망은 대시보드와 무관합니다.
- 전환: 과 이름▾ → 목록. 주소에 `#schedule/대시보드ID` 가 붙으므로 그 주소를 공유하면 바로 그 대시보드가 열립니다. 상단에는 지휘역량강화센터 → ICTC, 교육지원과 → 지원, 교육기획과 → 기획, 훈련운영과 → 훈련 으로 짧게 표시됩니다.
- 이름 변경·삭제: 목록 안의 연필·휴지통, 또는 ⋮ → **대시보드 이름 변경** / **이 대시보드 삭제**. 삭제하면 그 안의 일정·업무가 휴지통으로 가며(30일), 기본 대시보드는 삭제되지 않습니다.
- 직원이 실수로 다른 대시보드로 바꾸면 "일정이 안 보여요"라고 합니다. 과 이름▾에서 지휘역량강화센터를 다시 고르게 하세요.

## 5. 백업과 복구

| 방법 | 절차 | 범위 |
|---|---|---|
| **휴지통 복구** | 관리자 모드 ⋮ → **휴지통** → 항목 옆 **복구**. 종류(일정·업무·개인업무·41망)·제목·대시보드·삭제 시각·사유(삭제 / JSON 가져오기로 교체 / 대시보드 삭제 / 사용자 삭제)가 보임 | 30일 안에 지워진 일정·업무·개인업무·41망 글(삭제한 글의 원문). 일정을 지우면 연동 주요업무 카드도 함께 휴지통에 가고, 복구하면 함께 돌아옴. 톡방이 300개를 넘어 밀려난 옛 글은 복구 불가 |
| 휴지통 SQL | `select seq, kind, board, deleted_at, reason, data->>'title' as title from ictc_deleted_list('편집PIN');` → `select ictc_restore('편집PIN', seq값);` | 같음 |
| JSON 내보내기 (**주 1회 권장**) | 관리자 모드 ⋮ → **JSON 내보내기 (백업)**. Schedule·Attention 탭에서 각각, 대시보드마다. Individual Log 탭에서 누르면 **그 기기에 로그인한 사람의** 개인업무만 | 현재 대시보드의 해당 탭 |
| JSON 가져오기 | ⋮ → **JSON 가져오기 (통째로 교체)** → 파일 선택. **현재 대시보드의 해당 탭 전체가 교체**됩니다. 확인 창의 "현재 N건을 파일의 M건으로 교체" 숫자를 보고 누르세요. 덮어쓴 항목은 휴지통에 남음 | 복구·이전용(Schedule·Attention 만) |
| Supabase 자체 백업 | Supabase 대시보드 → Database → Backups. 무료 플랜은 일일 백업 7일 보관(플랜에 따라 다름) | DB 전체(첨부파일 제외) |
| 표 복사 | SQL Editor: `select * from ictc_items;` 결과를 CSV 로 내려받기 | DB 전체(개인업무·41망 글 포함) |

- 개인업무 JSON 가져오기는 없습니다(엑셀 가져오기만). 직원 전체 개인업무 보관은 Supabase 백업이나 SQL 로.
- 첨부파일은 DB 백업에 포함되지 않습니다. Storage → sail41 에서 폴더 단위로 내려받을 수 있습니다.
- 같은 id 가 다시 만들어져 있으면 복구 시 보관본으로 덮어씁니다. 30일이 지났으면 JSON 백업에서 그 항목만 찾아 화면에서 다시 입력합니다.

## 6. 무료 플랜 일시중지 복구

Supabase 무료 프로젝트는 **7일간 요청이 없으면 일시중지(Paused)** 됩니다. 증상: 잠금 화면·토스트에 "서버에 연결할 수 없어요. 와이파이·데이터 연결을 확인하고 다시 시도하세요", 목록에 "서버에 연결하지 못했어요 / 다시 시도", 하단에 "연결 안 됨 · …".
복구: https://supabase.com/dashboard → 프로젝트 → **Restore project** → 1~2분 뒤 정상. 데이터는 유지됩니다.
팀이 매주 쓰면 발생하지 않습니다. 장기 휴무 전에 한 번 열어 두면 예방됩니다.

## 8. SQL 재적용 (supabase.sql 이 바뀌었을 때)

`server/supabase.sql` 이 바뀌어 `main` 에 푸시되면 GitHub Actions "Apply Supabase SQL" 이 자동으로 DB에 실행합니다. 에이전트 보고에 "Actions 자동 적용 확인 또는 SQL Editor 재실행" 이 있으면 아래 순서로 확인합니다.

1. https://github.com/kwonyujin119/test2/actions → 왼쪽 **Apply Supabase SQL** → 맨 위 실행이 **초록 체크**면 끝. 로그 마지막 "적용 결과 확인" 단계에 `functions: N`, `policies(must be 0): 0` 이 보입니다.
2. **빨간 X** 면 그 실행을 눌러 "SQL 실행" 단계의 마지막 ERROR 줄을 봅니다. "실패 원인 안내" 단계가 흔한 원인 6가지를 알려 줍니다(비밀번호 오타 → Secret 갱신 / Direct 주소 → Session pooler 로 교체 / 프로젝트 일시중지 → Restore 후 **Run workflow**).
3. Actions 로 해결이 안 되면 수동 적용: https://supabase.com/dashboard → 프로젝트 → **SQL Editor** → **New query** → 저장소의 `server/supabase.sql` 전체(https://github.com/kwonyujin119/test2/blob/main/server/supabase.sql → **Raw** → 전체 선택·복사)를 붙여넣고 **Run**. 여러 번 실행해도 안전하고 기존 PIN·데이터는 유지됩니다.
4. 적용 뒤 보드를 새로고침(Ctrl+F5)해 잠금 화면 → 목록이 정상인지, 41망 첨부가 올라가는지 확인합니다.

실패해도 이전 함수는 그대로 남아 보드는 계속 동작합니다. 다만 새 기능(예: 새 RPC)은 잠금 화면의 영문 "Could not find the function …" 으로 막힙니다.

## 9. 첨부파일 저장소(Storage) 용량 관리

- 저장 위치: Supabase → **Storage** → 버킷 `sail41` → `chat/<톡방id>/`. 사진은 원본(최대 2048px) + 썸네일(480px) 두 파일로 저장됩니다.
- 한도: **무료 플랜 저장 용량 1GB, 파일당 50MB**(프로젝트 전체 상한. 버킷 설정은 100MB 지만 플랜이 우선). 화면은 한 번에 10개·100MB 까지 고를 수 있어 50MB 를 넘는 파일은 올리다가 "파일이 너무 커요. 서버 한도(무료 요금제는 파일당 50MB)보다 작게 줄여서 보내세요" 로 실패합니다. 직원에게는 "사진·문서만, 동영상은 올리지 말 것"으로 안내하세요.
- 허용 형식: 이미지(jpg·png·gif·webp·heic) · PDF · txt · csv · zip · 한글(hwp·hwpx) · 워드·엑셀·파워포인트. 그 외는 "올릴 수 없는 파일 형식이에요. 사진·문서·압축 파일로 바꿔 보내세요".
- 사용량 확인: Supabase → **Settings → Usage**(또는 Storage 화면 상단). 80% 를 넘으면 정리합니다.
- 정리: Storage → sail41 → chat → 오래된 톡방 폴더/파일 선택 → **Delete**. 글은 남고 그 첨부만 "링크 깨짐"이 됩니다. 글을 지워도 파일은 자동으로 지워지지 않습니다(글 삭제 시 "첨부 파일은 저장소에 남아요" 안내가 뜨는 이유).
- 보안: 업로드 자체는 anon 키로 `chat/` 경로에만 가능하고, 앱이 입장코드를 먼저 확인한 뒤 올립니다. anon 키를 아는 사람이 직접 올리는 것은 막지 못하므로(Storage 정책 한계) 용량이 갑자기 늘면 폴더를 확인하세요.
- "파일 저장소가 아직 준비되지 않았어요. 담당자에게 알려 주세요(SQL 재적용)" → 버킷이 없음. 8장으로 SQL 재적용. 그래도 안 되면 Storage 에서 **New bucket** → 이름 `sail41`, Public 체크 후 다시 SQL 실행(정책 생성).

# 담당자 운영 가이드

대상: 보드 담당자(편집 PIN 보유, Supabase·GitHub 계정 소유). 직원 안내는 [`직원안내.md`](직원안내.md).

용어: 화면에서 직원에게 보이는 "팀 PIN"이 **조회 PIN**, "관리자"가 **편집 PIN** 입니다. 이 문서는 SQL 함수 이름과 맞추기 위해 조회 PIN·편집 PIN 으로 씁니다.

## 1. 구성 한눈에

| 구성 요소 | 위치 | 역할 |
|---|---|---|
| 화면 | https://kwonyujin119.github.io/test2/ (GitHub Pages, 저장소 `kwonyujin119/test2`) | 보드 웹앱. `index.html` 하나 |
| 데이터 | Supabase 프로젝트 "IFA DASHBOARD" (Southeast Asia, Singapore) | 일정·업무·대시보드·개인업무 사용자 |
| 연결 설정 | 저장소 `config.js` | Supabase URL + anon 키(공개 키) + 갱신 주기(30초) |
| DB 구조 | 저장소 `server/supabase.sql` | 테이블·함수. 바뀌면 DB에 다시 실행해야 함 |
| 자동 적용 | GitHub Actions "Apply Supabase SQL" | `supabase.sql` 푸시 시 자동 실행. Secret `SUPABASE_DB_URL` 필요(설정 완료) |

## 2. 권한 구조 (2026-10 기준)

| 작업 | 조회 PIN(직원) | 편집 PIN(담당자) |
|---|---|---|
| 일정·주요업무 보기 · **추가 · 수정 · 삭제** | ○ | ○ |
| 개인업무 등록·기록(본인) | ○ | ○ |
| 대시보드 추가 · 이름 변경 · 삭제 | | ○ |
| JSON 가져오기(탭 전체 교체) · JSON 내보내기 | | ○ |
| 개인업무 사용자 관리(목록·삭제) | | ○ |
| 조회 PIN 다시 입력 · 편집 PIN 변경 | | ○ |

**직원 누구나 삭제할 수 있고, 직원 화면에는 되돌리기가 없습니다.** 지운 항목은 휴지통에 30일 보관되므로 담당자가 관리자 모드 ⋮ → 휴지통에서 복구할 수 있습니다(5장). 그래도 5장의 JSON 백업을 **주 1회** 받아 두세요.

관리자 모드 켜기: 보드 제목을 **0.7초 길게 누르기** → 편집 PIN 입력. 또는 대시보드 **+** 처럼 관리 작업을 누르면 PIN을 묻습니다. 켜지면 화면 테두리가 초록 그라데이션, 제목 옆 "● 관리자" 배지, ⋮ 메뉴에 관리 항목 전부가 보입니다.
끄기: ⋮ → **관리자 모드 해제**. 공용 PC에서 관리 작업을 했다면 꼭 끄세요. 켜진 채 두면 그 기기를 쓰는 누구나 대시보드를 지울 수 있습니다.

## 3. PIN · 사용자 관리

### 화면에서 (관리자 모드)

| 할 일 | 위치 |
|---|---|
| 등록된 개인업무 사용자 보기 · 삭제(그 사람 개인업무 포함) | ⋮ → **개인업무 사용자 관리** |
| 편집 PIN을 이 기기에 저장 / 바꿔 저장 | ⋮ → **관리자(편집 PIN) 입력/변경** (서버의 PIN을 바꾸는 게 아니라 기기에 저장된 값만 바꿉니다) |
| 조회 PIN 잠금 화면 다시 열기 | ⋮ → **조회 PIN 다시 입력** |

### SQL 로 (Supabase → SQL Editor → New query → 붙여넣고 Run)

| 할 일 | SQL |
|---|---|
| 편집 PIN 변경 | `select ictc_set_pin('기존편집PIN', '새편집PIN');` (4자 이상) |
| 조회 PIN 변경 | `select ictc_set_view_pin('편집PIN', '새조회PIN');` |
| 조회 PIN 없애기(링크만 알면 누구나) | `select ictc_set_view_pin('편집PIN', '');` |
| 개인업무 비밀번호 초기화 | 화면: ⋮ → 개인업무 사용자 관리 → **비밀번호**. SQL: `select ictc_user_reset_pin('편집PIN', '뒤4자리', '새비밀번호4자리');` |
| 개인업무 이름 수정 | 화면: ⋮ → 개인업무 사용자 관리 → **이름**. SQL: `select ictc_user_rename('편집PIN', '뒤4자리', '바른이름');` |
| 등록된 개인업무 사용자 보기 | `select * from ictc_users_list('편집PIN');` |
| 개인업무 사용자 삭제 | `select ictc_user_delete('편집PIN', '뒤4자리');` |
| 현재 PIN 확인 | `select * from ictc_settings;` |

- PIN을 바꾸면 모든 직원 기기에 잠금 화면이 다시 뜹니다. **바꾸기 전에** 새 PIN을 공지하세요.
- 편집 PIN은 조회 PIN을 겸합니다.
- PIN을 연속으로 틀리면 서버가 응답을 늦춥니다(무차별 대입 방지). 정상 사용에는 영향 없습니다.
- 개인업무 열쇠는 뒤 4자리 + **비밀번호 4자리**(본인이 정함, 서버에는 해시만 저장. 담당자도 볼 수 없음). 잊었다고 하면 사용자 관리에서 **비밀번호**를 눌러 새 4자리를 정해 알려 주고, 본인이 ⋮ → 내 비밀번호 변경으로 바꾸게 하세요. 이름 오타는 **이름** 버튼으로 고치면 업무가 그대로 남습니다(삭제 후 재등록은 개인업무가 지워짐).
- v4 이전(이름으로 로그인하던) 사용자는 '처음 등록' 탭에서 같은 이름 + 새 비밀번호를 넣으면 자동 전환됩니다. 이름이 기억나지 않는다고 하면 사용자 관리에서 이름을 확인해 주세요.
- 같은 행정전화를 두 명이 쓰면 둘째 사람은 등록할 수 없습니다. 그 사람에게는 안 쓰는 4자리(예: 내선번호)를 정해 주고 그 번호로 등록하게 하세요.

## 4. 대시보드 관리 (화면에서, 관리자 모드)

- 추가: 제목 옆 **+** → 이름 → 편집 PIN. 대시보드마다 일정·주요업무가 따로 저장됩니다. 개인업무는 대시보드와 무관하게 사람별입니다.
- 전환: 제목 ▾ 클릭 → 목록. 주소에 `#schedule/대시보드ID` 가 붙으므로 그 주소를 공유하면 바로 그 대시보드가 열립니다.
- 이름 변경·삭제: 제목 ▾ 목록 안의 연필·휴지통, 또는 ⋮ 메뉴. 삭제하면 그 안의 일정·업무가 모두 지워지며 되돌릴 수 없습니다. 기본 대시보드는 삭제되지 않습니다.
- 용도 예: 기수별 교육과정, 연도별 계획, 행사 준비.

## 5. 백업과 복구

| 방법 | 절차 | 범위 |
|---|---|---|
| JSON 내보내기 (**주 1회 권장**) | 관리자 모드 ⋮ → JSON 내보내기. Schedule·Attention 탭에서 각각, 대시보드마다 | 현재 대시보드의 해당 탭 |
| JSON 가져오기 | ⋮ → JSON 가져오기 → 파일 선택. **현재 대시보드의 해당 탭 전체가 교체**됩니다. 확인 창에 "현재 N건을 파일의 M건으로 교체"가 뜨니 숫자를 보고 누르세요 | 복구·이전용 |
| Supabase 자체 백업 | Supabase 대시보드 → Database → Backups. 무료 플랜은 일일 백업 7일 보관(플랜에 따라 다름) | DB 전체 |
| 표 복사 | SQL Editor: `select * from ictc_items;` 결과를 CSV 로 내려받기 | DB 전체(개인업무 포함) |
| **휴지통 복구** | 관리자 모드에서 ⋮ → **휴지통** → 항목 옆 **복구**. SQL 로도 가능: `select seq, kind, board, deleted_at, reason, data->>'title' as title from ictc_deleted_list('편집PIN');` 로 찾고 → `select ictc_restore('편집PIN', seq값);` | 30일 안에 지워진 일정·업무·대시보드·개인업무 |

- 개인업무는 본인이 Individual Log 탭에서 자기 것만 JSON 내보내기 할 수 있고, 가져오기는 없습니다. 전체 보관은 Supabase 백업이나 SQL 로.
- 직원이 "잘못 지웠어요"라고 하면: 위 휴지통 SQL 로 제목·삭제 시각을 보고 `ictc_restore` 로 되살립니다. 같은 id 가 다시 만들어져 있으면 보관본으로 덮어씁니다. 30일이 지났으면 JSON 백업에서 그 항목만 찾아 화면에서 다시 입력합니다. JSON 가져오기는 탭 전체를 덮어쓰므로 그 사이에 다른 사람이 넣은 항목이 사라집니다(덮어쓴 항목도 휴지통에 남습니다).

## 6. 무료 플랜 일시중지 복구

Supabase 무료 프로젝트는 **7일간 요청이 없으면 일시중지(Paused)** 됩니다. 증상: 화면에 "서버에 연결하지 못했어요".
복구: https://supabase.com/dashboard → 프로젝트 → **Restore project** → 1~2분 뒤 정상. 데이터는 유지됩니다.
팀이 매주 쓰면 발생하지 않습니다. 장기 휴무 전에 한 번 열어 두면 예방됩니다.

## 7. 흔한 증상 → 원인 → 조치

| 증상 | 원인 | 조치 |
|---|---|---|
| 잠금 화면 없이 "테스트 모드" 배너가 뜸 | `config.js` 값이 비었거나 Pages 반영 전 | 저장소 `config.js` 확인. 푸시 후 2분 뒤 Ctrl+F5 |
| 잠금 화면에서 "연결 실패: 서버 응답 404" 또는 `function … does not exist` | DB에 최신 `supabase.sql` 미적용 | Actions 탭 "Apply Supabase SQL" 성공 여부 확인. 실패·미실행이면 SQL Editor 에서 파일 전체 Run |
| "연결 실패: 서버 응답 401/403" | anon 키 오류 또는 키 교체됨 | Supabase → Project Settings → API Keys 와 `config.js` 대조 |
| "서버에 연결하지 못했어요" 계속 | 프로젝트 일시중지 또는 네트워크 | 6장. 기관망에서 supabase.co 차단 여부는 전산 담당 문의 |
| 직원 화면에 "편집 PIN이 올바르지 않습니다" | 직원이 대시보드 **+** 같은 관리 버튼을 누르고 조회 PIN을 넣음 | 조치 불필요. 직원에게 "그 버튼은 담당자용"이라고 안내 |
| 직원 기기에 초록 테두리 | 그 기기에 편집 PIN이 저장됨(담당자가 그 기기에서 작업했거나 PIN이 새어 나감) | ⋮ → 관리자 모드 해제. PIN 유출이 의심되면 3장 SQL 로 편집 PIN 변경 |
| Actions 가 빨간 X | Secret 누락·오타, Session pooler 가 아닌 주소, 비밀번호 특수문자 | Actions 로그의 "SQL 실행" 단계 확인. Secret 을 Session pooler 주소로 다시 저장 |
| 직원이 항목을 잘못 지움 | 조회 PIN 으로 누구나 삭제 가능 | 5장 휴지통 복구(30일 이내) |
| 일정이 다른 대시보드에 저장됨 | 입력 당시 선택된 대시보드가 달랐음 | 해당 항목 삭제 후 올바른 대시보드에서 재입력 |
| 일정을 "주요업무"로 저장했는데 화면이 Attention 탭으로 바뀜 | 정상 동작. 연동 카드가 만들어져 그 탭으로 이동 | Schedule 탭에도 그대로 있음 |
| 홈 화면 추가 카드가 안 뜸 | 이미 설치됨, "나중에"를 눌러 7일 숨김, 또는 인앱 브라우저 | ⋮ → 홈 화면에 추가. 네이버·카톡 안이면 "브라우저로 열기" |

## 8. 비밀값 취급 원칙

| 값 | 성격 | 둘 곳 |
|---|---|---|
| anon 키 (`eyJ…` 또는 `sb_publishable_…`) | 공개 키. 브라우저에 노출되도록 설계 | `config.js` (커밋 가능) |
| 조회 PIN / 편집 PIN | 팀 비밀 | 직원 공지·담당자 메모. 코드·문서에 쓰지 않음 |
| DB 비밀번호, Session pooler 접속 문자열 | **DB 전체 권한** | GitHub Secret `SUPABASE_DB_URL` 에만. 채팅·메모앱·문서에 남기지 않음 |
| `service_role` / `sb_secret_…` 키 | **DB 전체 권한** | 어디에도 쓰지 않음. 복사하지 않음 |

AI 에이전트(Claude)에게 작업을 맡길 때도 위 비밀값은 붙여 넣지 않습니다. anon 키와 Project URL 만 전달하면 됩니다.

## 9. 기능 수정 요청 흐름

1. 요구사항을 한국어로 정리해 Claude 세션에 전달. 화면은 **불빛**, 저장 구조·서버는 **불씨**, 안내문·운영은 **횃불** 에이전트가 맡습니다([`SIGNATURE.md`](../SIGNATURE.md), 규칙은 [`CLAUDE.md`](../CLAUDE.md)).
2. 푸시 후 1~2분 뒤 사이트에 반영. `server/supabase.sql` 이 바뀐 경우 Actions 자동 적용(초록 체크)을 확인합니다.
3. 반영 확인은 휴대폰과 PC 양쪽에서. 문제가 있으면 화면 캡처와 함께 알립니다.

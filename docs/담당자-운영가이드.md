## 2. PIN 관리 (Supabase → SQL Editor → New query → 붙여넣고 Run)

| 할 일 | SQL |
|---|---|
| 편집 PIN 변경 | `select ictc_set_pin('기존편집PIN', '새편집PIN');` (4자 이상) |
| 조회 PIN 변경 | `select ictc_set_view_pin('편집PIN', '새조회PIN');` |
| 조회 PIN 없애기(누구나 조회) | `select ictc_set_view_pin('편집PIN', '');` |
| 개인업무 이름 정정 | `select ictc_user_reset_pin('편집PIN', '뒤4자리', '바른이름');` |
| 등록된 개인업무 사용자 보기 | `select * from ictc_users_list('편집PIN');` (이름·등록일·업무 건수) |
| 퇴직자 등 개인업무 사용자 삭제(그 사람 개인업무 포함) | `select ictc_user_delete('편집PIN', '뒤4자리');` |
| 현재 PIN 확인 | `select * from ictc_settings;` |

- PIN을 바꾸면 모든 직원 기기에 잠금 화면이 다시 뜹니다. 바꾸기 전에 새 PIN을 공지하세요.
- 편집 PIN은 조회 PIN을 겸합니다. 편집 PIN 보유자는 조회 PIN을 몰라도 들어갑니다.
- PIN을 연속으로 틀리면 서버가 응답을 잠시 늦춥니다(무차별 대입 방지). 정상 사용에는 영향 없습니다.
- 개인업무는 뒤 4자리 + 이름이 곧 열쇠입니다. 직원이 이름을 잘못 등록했으면 위 정정 SQL 로 바꾸고, 직원은 바른 이름으로 다시 들어가면 됩니다.

## 3. 대시보드 관리 (화면에서)

- 추가: 제목 옆 **+** → 이름 입력 → 편집 PIN. 대시보드마다 일정·주요업무가 따로 저장됩니다. 개인업무는 대시보드와 무관하게 사람별입니다.
- 전환: 제목(지휘역량강화센터 ▾) 클릭 → 목록에서 선택. 주소에 `#schedule/대시보드ID` 가 붙으므로 그 주소를 공유하면 바로 그 대시보드가 열립니다.
- 이름 변경·삭제: ⋮ 메뉴. 삭제하면 그 안의 일정·업무가 모두 지워지며 되돌릴 수 없습니다. 기본 대시보드는 삭제되지 않습니다.
- 용도 예: 기수별 교육과정, 연도별 계획, 행사 준비.

## 4. 백업과 복구

| 방법 | 절차 | 범위 |
|---|---|---|
| JSON 내보내기 (수시) | 화면 ⋮ 메뉴 → JSON 내보내기. 일정표·주요업무 탭에서 각각, 대시보드마다 | 현재 대시보드의 해당 탭 |
| JSON 가져오기 | ⋮ → JSON 가져오기 → 파일 선택. **현재 대시보드의 해당 탭 전체가 교체**됩니다 | 복구·이전용 |
| Supabase 자체 백업 | Supabase 대시보드 → Database → Backups. 무료 플랜은 일일 백업 7일 보관(플랜에 따라 다름) | DB 전체 |
| 표 복사 | SQL Editor: `select * from ictc_items;` 결과를 CSV 로 내려받기 | DB 전체 |

개인업무는 JSON 내보내기에 포함되지 않습니다(개인별 데이터). 필요하면 Supabase 백업이나 SQL 로 보관하세요.

## 5. 무료 플랜 일시중지 복구

Supabase 무료 프로젝트는 **7일간 요청이 없으면 일시중지(Paused)** 됩니다. 증상: 화면에 "서버에 연결하지 못했어요".
복구: https://supabase.com/dashboard → 프로젝트 선택 → **Restore project** 버튼 → 1~2분 뒤 정상. 데이터는 유지됩니다.
팀이 매주 사용하면 발생하지 않습니다. 장기 휴무 전에 한 번 열어 두면 예방됩니다.

## 6. 흔한 오류 → 원인 → 조치

| 증상 | 원인 | 조치 |
|---|---|---|
| 사이트가 잠금 화면 없이 "미리보기 모드"로 뜸 | `config.js` 값이 비었거나 Pages 반영 전 | 저장소 `config.js` 확인. 푸시 후 2분 뒤 Ctrl+F5 |
| 잠금 화면에서 "연결 실패: 서버 응답 404" 또는 `function … does not exist` | DB에 최신 `supabase.sql` 미적용 | Actions 탭에서 "Apply Supabase SQL" 성공 여부 확인. 실패·미설정이면 SQL Editor 에서 파일 전체 Run |
| "연결 실패: 서버 응답 401/403" | anon 키 오류 또는 키 교체됨 | Supabase → Project Settings → API Keys 의 키와 `config.js` 대조 |
| "서버에 연결하지 못했어요" 가 계속됨 | 프로젝트 일시중지 또는 네트워크 | 5번 절차. 기관망에서 supabase.co 차단 여부는 전산 담당 문의 |
| 직원 저장이 "편집 PIN이 올바르지 않습니다" | PIN 변경 후 옛 PIN 저장됨 | 새 PIN 공지. 직원은 다음 저장 때 다시 입력 |
| Actions 가 빨간 X | Secret 누락·오타, Session pooler 가 아닌 주소, 비밀번호 특수문자 | Actions 로그의 "SQL 실행" 단계 확인. Secret 을 Session pooler 주소로 다시 저장 |
| 일정이 다른 대시보드에 저장됨 | 입력 당시 선택된 대시보드가 달랐음 | 해당 항목 삭제 후 올바른 대시보드에서 재입력 |

## 7. 비밀값 취급 원칙

| 값 | 성격 | 둘 곳 |
|---|---|---|
| anon 키 (`eyJ…` 또는 `sb_publishable_…`) | 공개 키. 브라우저에 노출되도록 설계 | `config.js` (커밋 가능) |
| 조회 PIN / 편집 PIN | 팀 비밀 | 직원 공지·담당자 메모. 코드·문서에 쓰지 않음 |
| DB 비밀번호, Session pooler 접속 문자열 | **DB 전체 권한** | GitHub Secret `SUPABASE_DB_URL` 에만. 채팅·메모앱·문서에 남기지 않음 |
| `service_role` / `sb_secret_…` 키 | **DB 전체 권한** | 어디에도 쓰지 않음. 복사하지 않음 |

AI 에이전트(Claude)에게 작업을 맡길 때도 위 비밀값은 붙여 넣지 않습니다. anon 키와 Project URL 만 전달하면 됩니다.

## 8. 기능 수정 요청 흐름

1. 요구사항을 한국어로 정리해 Claude 세션에 전달. 화면 변경은 "화면(불빛)", 저장 구조 변경은 "데이터(불씨)", 안내문은 "운영(횃불)" 에이전트가 맡습니다([`SIGNATURE.md`](../SIGNATURE.md)).
2. 푸시 후 1~2분 뒤 사이트에 반영. `server/supabase.sql` 이 바뀐 경우 Actions 자동 적용을 확인합니다.
3. 반영 확인은 휴대폰과 PC 양쪽에서. 문제가 있으면 화면 캡처와 함께 알립니다.
